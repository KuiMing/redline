# 奧援系列共用 Hook 與生命週期稽核

日期：2026-08-07

## 範圍

依 `rules.md` 的共用規則，並逐項對照：

- `data/raw/support_cards.csv`
- `data/cards/support_taxonomy.v1.1.json`
- `server/game.py`
- 正式 WebSocket／瀏覽器 UI

稽核全部九個系列：英美、東洋、南洋、印度、天方、歐洲、北國、臺灣、紅軍奧援。

完整追蹤生命週期：

`play_card → reaction → commit/cancel → pending choice → resolve → discard/return`

另檢查：事件進度、出牌後陣營能力、建設／瓦解 hooks、年代效果、共用組織、固定購買供應、借用牌歸還、卡牌只棄置一次及正式 UI 可操作性。

## 確認並修正的缺陷

1. **印度奧援憑空建立分神**：I／II／III 原本直接建立 1／2／3 張新卡，未消耗固定購買供應。現在只從 `static_purchase_supply` 取得實體供應；不足時少放並記錄。
2. **印度研究分析室繞過延後反應與事件 hook**：能力移入統一 committed-card hook；未取消才觸發、取消不觸發、互動結束後只觸發一次，並計入 `use_faction_ability`。
3. **取消北國奧援未回復出牌組合**：取消初始選擇現在會恢復 `played_nonstarter_names`，不會錯誤達成「展現實力」。
4. **借用北國奧援無法取消**：借用牌已先回原持有者牌庫頂，舊 rollback 找不到卡。現在依實體卡物件跨 zone 找回，恢復借用歸還 marker，再放回出牌者原手牌位置。
5. **共用組織沒有完整套入奧援距離／目標規則**：東洋建立起點、天方距離判定、北國與臺灣瓦解起點／目標、北國 I 犧牲目標，現在都使用共用組織視角；實際瓦解或犧牲時仍移除正確實體持有者的組織。
6. **臺灣奧援 III 首次命中紅軍根據地後誤報失敗**：首次命中已成功，但根據地尚未被第二次命中移除，所以不建立。現在回傳 `success=true, red_base_hit=true, built=false`，不再在盤面已變更後回傳整體錯誤；第二次命中後的正常補位維持不變。
7. **互動奧援 resolve-time 目標失效會消耗流程**：現在會重算候選；仍有合法目標時保留 pending choice 讓玩家重選，完全無目標時以明確 fizzle 結束，不會留下死鎖。
8. **紅軍奧援被誤標成 1 資金＋1 宣傳購買費用**：紅軍奧援是起始牌，購買費用現在為 0／0；反應卡取消它時不再錯拿依被取消牌購買費用判定的 bonus 抽牌。普通奧援仍依印刷購買費用參與相關事件／陣營能力。
9. **取消反應 UI 被「其他玩家動態」遮住**：目前 viewer 有 `reaction_choice` 時會優先關閉轉播疊層，避免攔截反應按鈕；同一則通知不會在反應後重播。

## 資料層注意事項

`support_taxonomy.v1.1.json` 的 `tier_*_kind` 是摘要分類，無法單獨完整表達南洋 I 的「抽後棄牌」、北國 I 的「先犧牲後瓦解」、臺灣 III 的「瓦解後同地建立」等複合效果；runtime 目前以完整 mapping 實作並已驗證。後續若要讓 taxonomy 成為可直接執行的效果來源，應另做 schema 升級，不應把目前的摘要 kind 當成完整規則。
