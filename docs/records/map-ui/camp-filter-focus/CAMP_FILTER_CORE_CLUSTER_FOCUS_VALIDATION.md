# 陣營篩選「聚焦結果」聚焦主要群集驗證

使用者回報：戰略地圖選「陣營」篩選為香港後按「聚焦結果」，畫面不會真的 zoom in 到香港
地區。使用者明確要求：篩選結果本身仍要包含河內、胡志明市、臺灣三座城鎮（它們是香港
陣營合法的建立組織城鎮），但聚焦計算應該更看重香港本身。

## 根因

`fitVisible()` 的陣營篩選分支，聚焦中心早就已經用「篩選結果座標中位數」計算（不會被
離群點拉走），但縮放層級 `targetZoom` 仍然沿用 `map.getBoundsZoom()` 對「全部篩選結果」
原始 bounds 算出來的 `fittedZoom`——只是事後夾在 4~9 之間，中心點修對了、縮放程度還是
被離群城鎮拖低。

實測「香港」陣營篩選結果其實有 27 個城鎮，不只使用者提到的河內/胡志明/臺灣，還包含
廣州、東沙、澳門，甚至「倫敦」（town 資料裡陣營標籤範圍比想像中廣）。

## 修法

新增 `coreClusterTowns()`：以篩選結果座標中位數為聚焦中心，計算每個城鎮與中心的距離，
取「距離中位數」代表主要群集的典型半徑（對離群點本身穩健，不會被單一極端離群點——例如
倫敦——拉歪門檻），距離超過典型半徑 4 倍（下限 0.5 度）的城鎮視為明顯偏遠據點。聚焦中心
與縮放層級都只用主要群集計算；篩選結果（含偏遠據點）本身完全不變，仍完整顯示在地圖上，
玩家可平移查看。城鎮本身分布均勻、切不出明顯主要群集時（例如反賊、紅軍這類本來就遍布
全圖的陣營），門檻內幾乎涵蓋全部結果，等同沿用原本行為，不會強行拆分。

第一版曾嘗試「排序後找最大間隔」的分群方式，但被倫敦這個極端離群點主導了間隔位置，導致
臺灣/河內/廣州仍全部被視為「主要群集」一部分（`coreCount: 26/27`，縮放層級仍只有 5）；
改成「典型半徑倍數」門檻後才正確排除到只剩香港本身＋澳門（`coreCount: 18/27`，縮放層級
達到上限 9）。

## 驗證

- 程式化讀取 `window.__lastFilterFocus`：香港陣營篩選 27 個結果、18 個納入主要群集、
  縮放層級從原本的 5 提升到上限 9；臺灣（70 結果／65 主要群集）、反賊（62／61）、紅軍
  （176／176）這幾個本來就分布廣泛的陣營，門檻內幾乎涵蓋全部結果，縮放層級維持原本的 4，
  沒有回歸問題。
- `hongkong_focused_core_cluster.png`——實際截圖確認香港本身的城鎮群清楚填滿畫面，河內/
  胡志明/臺灣雖然不在目前視野內，但仍是篩選結果的一部分（`resultCount` 未減少），可平移
  查看。
- 完整 pytest 366/366 passed（純前端地圖渲染改動，不影響後端邏輯）。
