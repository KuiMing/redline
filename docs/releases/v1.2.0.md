# REDLINE v1.2.0

v1.2.0 新增 in-repo REDLINE MCP server 與自動化紅軍控制器，讓 MCP 相容的 LLM Agent（Claude Code、OpenAI Codex 等）可以直接連上遊戲、扮演紅軍跟真人對局，並修正兩個在實際對局中發現的問題。

## 新功能

- **REDLINE MCP server**（`mcp_server/`）：MCP 相容的 LLM client 可以透過既有的 HTTP/WebSocket API 建立或加入房間、選陣營、讀取自己的隱私範圍狀態、查詢目前合法動作並實際下棋，支援 stdio 與 Streamable HTTP 兩種傳輸方式。
- **自動化紅軍控制器**（`red_army_controller/`）：主機端等待真人時不呼叫模型，只在紅軍需要決策時喚起 Agent；支援自訂 Agent runner adapter（Claude Code、Codex 或其他）。
- **Docker Compose 一鍵啟動**：`docker-compose.yml` 一次啟動遊戲伺服器與 MCP server；MCP 端預設只綁定 `127.0.0.1`、開啟 DNS-rebinding 防護，不會不小心暴露到 LAN 或公網。
- **`.mcp.json`**：Claude Code 開啟本 repo 時會自動偵測到專案層級的 MCP server 設定，不需要手動執行 `claude mcp add`。
- **`skills/play-redline/SKILL.md`** 與 README「讓 Agent 陪你玩」章節：說明怎麼讓任何 MCP 相容 Agent 扮演紅軍、跟真人對局，並自動輪詢偵測輪到自己的回合。

## 修正

- 紅軍能力（國安部／政工部／中紀委）在合法但目前沒有可用目標時，伺服器原本算好的說明訊息會被 WebSocket 派送層靜默吞掉，畫面看起來像「動作成功但沒反應」——瀏覽器介面與 MCP 皆受影響，現已修正為正確回傳錯誤訊息。
- MCP 的 `get_legal_actions` 過去只要本回合購買的牌還留在棄牌堆，就會誤判「可使用頂牌權」，即使玩家實際上沒有被授予頂牌權，導致伺服器之後拒絕該動作；現已改為檢查真正的授權次數。

## 驗證摘要

- `PYTHONPATH=. uv run pytest scripts/tests/ -q`：1397 個測試全數通過（固定測試順序）。
- 實際透過 MCP 進行了兩場完整的多回合對局（Claude Code 扮演紅軍 vs. 真人），涵蓋本次修正的兩個問題點，紅軍皆獲勝。
- `docker compose up --build` 驗證兩個服務皆能正常啟動並回報健康。

## 升級說明

1. 取得 `v1.2.0` source：

   ```bash
   git checkout v1.2.0
   ```

2. 使用 uv 依鎖檔同步環境：

   ```bash
   uv sync --frozen
   ```

3. 啟動服務（三種方式，依方便程度排列，詳見 README）：

   ```bash
   docker compose up --build -d
   ```

此版本沒有破壞性的相依套件或資料格式變更，也不需要資料庫 migration。新增的 `mcp` 套件相依已加入 `pyproject.toml`／`uv.lock`。

## 已知限制

- 房間與遊戲狀態儲存在單一 Python process 的記憶體中。服務重啟時，現有房間與對局不會保留（含 MCP 連線的房間）。
- 請勿使用多 worker 或多 replica。
- MCP 的 Streamable HTTP 端點沒有內建身分驗證，設計上只給本機使用；若要對外開放，需要自行加上反向代理與驗證。
- 本專案是非官方二次創作。原作內容僅限非商用並須註明出處。
- 本次打版不包含正式容器替換、registry 發布或正式環境部署。
