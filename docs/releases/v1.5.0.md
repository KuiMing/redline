# REDLINE v1.5.0

v1.5.0 新增房主控制的程式化紅軍，校正事件整輪結算，並改善戰略地圖的道路與鐵路高亮。

## 新功能

- **程式化紅軍**：房主可在作戰準備室啟用「AI 紅軍」。程式化紅軍使用確定性的規則與評分策略，不需在每個紅軍決策呼叫外部模型。
- **可觀察的 AI 回合**：程式化紅軍在成功動作之間保留操作間隔，讓玩家可跟上盤面變化。

## 回合與事件規則

- **紅軍最後行動**：每一輪從紅軍座位後一席開始，紅軍固定在完整一輪的最後操作。
- **完整一輪後結算**：任務事件改為所有參與者各行動一次後才結算，不再因紅軍坐在中間座位而提早判定。
- **逐玩家判定**：每位非紅軍玩家各自追蹤、判定並套用任務事件結果。多位玩家的結果與待決選擇依座位順序處理。
- **稽核基準獨立**：14 張任務卡的結算時機使用固定、人工撰寫的 oracle 驗證，不再由被測資料產生預期值。

## 戰略地圖路線高亮

- **直接道路與鐵路**：選取有組織的來源城鎮時，直接相鄰道路與直接相鄰鐵路都會高亮。
- **不顯示遠端路徑聯集**：一般來源選取不再把所有遠端合法鐵路路徑聯集一起高亮。
- **特定目的地完整路徑**：指向特定合法多段鐵路目的地時，仍顯示伺服器投影的完整權威路徑。
- **福岡至仙臺回歸保護**：福岡 → 大阪 → 東京 → 仙臺仍會完整高亮三段鐵路。
- **合法性保持隔離**：高亮只提供視覺提示。它不會新增 action target，也不會讓非法目的地變成可點擊或可執行。

## 程式化紅軍改善

- 改善支援、瓦解及目標選擇的優先序。
- 避免重複或無效動作形成循環。
- 修正臺灣勝利條件文字與紅軍策略判定不一致的問題。
- Docker image 現在包含程式化紅軍需要的 runtime modules。

## 其他修正

- 修正「全國人大召開」等任務事件將所有玩家合併為單一全有或全無結果的問題。
- 修正蒙古「盟旗學校」在瓦解被阻止時仍誤記為已觸發的問題。
- 修正選取有己方組織的城鎮時，直接鐵路沒有高亮的問題。

## 升級說明

1. 取得 `v1.5.0` source：

   ```bash
   git checkout v1.5.0
   ```

2. 使用 uv 依鎖檔同步環境：

   ```bash
   uv sync --frozen
   ```

3. 啟動服務：

   ```bash
   docker compose up --build -d
   ```

此版本沒有破壞性的資料格式變更，也不需要資料庫 migration。

## 已知限制

- 房間與遊戲狀態儲存在單一 Python process 的記憶體中。服務重啟時，現有房間與對局不會保留。
- 請勿使用多 worker 或多 replica。
- MCP 的 Streamable HTTP 端點沒有內建身分驗證。此端點預設只供本機使用。若要對外開放，請自行加上反向代理與驗證。
- 本專案是非官方二次創作。原作內容僅限非商用並須註明出處。
- 本次打版不包含 image build、正式容器替換、registry 發布或正式環境部署。
