# REDLINE v0.3.0

v0.3.0 改善多人遊戲的公開結果提示、回合交接與戰況辨識，並完成核心遊戲及路由模組化。此版本也將可直接改動遊戲狀態的測試路由改為預設停用，並加入多視角 differential replay 驗證。

## 玩家可見變更

### 共用陣營能力結果

- 「立場試探」、「賭徒耳語」與「民族祭儀」的翻牌、猜測與獎勵結果，現在會透過中央結果視窗同步顯示給所有玩家。
- 回合交接給下一位玩家時，上一回合的結果視窗會自動關閉。
- 系統會核對目前視窗仍是原本的共享結果，避免誤關閉後續錯誤或待選視窗。
- 公開結果不會包含被放到牌庫底的私人手牌名稱。

### 紅軍特殊能力提示

- 「統戰部」、「政工部」、「國安部」與「中紀委」的公開結果，對其他玩家統一使用單一中央結果視窗。
- 同一結果不再同時顯示中央視窗及「其他玩家動態」。
- 紅軍發動者不會看到冗餘結果提示。
- 四種結果都會在回合交接時自動關閉，且不會在後續回合重新播放。

### 操作提示與戰況畫面

- 移除頂部窄條通知列，增加遊戲區域的可用空間。
- 無法使用的手牌、企業人脈結果與一般錯誤改用中央提示視窗。
- 等待其他玩家選擇根據地的資訊移至既有階段狀態區。
- 「戰況總覽」玩家卡片使用完整陣營色盤，補齊蒙古、滿洲及各反賊陣營的背景、邊框、頭像與徽章色彩。
- 修正過長的階段提示在滑鼠停留或鍵盤聚焦時被遊戲分頁或操作列遮住的問題。

## 安全性與操作變更

- `/test/*` HTTP 路由現在預設不掛載，避免正式服務暴露可直接修改遊戲狀態的 setup endpoint。
- 正式環境不應設定 `ENABLE_TEST_ROUTES=true`。
- Browser proof、手動驗證伺服器或需要 setup endpoint 的 CI，必須明確啟用：

  ```bash
  ENABLE_TEST_ROUTES=true \
    uv run uvicorn server.main:app --host 0.0.0.0 --port 8000
  ```

## 開發與維護變更

- 將 `server/game.py` 的卡牌播放、待選效果、反應鏈、事件、時代、陣營、地圖、購買、組織與狀態投影邏輯拆成較小模組。
- 將 `server/main.py` 的 Lobby、地圖資料及測試 setup API 拆成獨立路由模組。
- 保留主要既有匯入方式及 in-process 測試 callable，降低重構對既有工具的影響。
- 新增四組 deterministic multi-viewer differential replay fixtures，涵蓋一般雙人流程、陣營能力、紅軍特殊行動及一般主動能力。
- Replay harness 會固定 random seed，並在每個 checkpoint 比較所有玩家與 public view 的完整狀態。
- 驗證腳本集中移至 `scripts/validate/`；引用舊 `scripts/validate_*.py` 路徑的外部工具需要更新。

## 升級說明

1. 取得 v0.3.0 source：

   ```bash
   git checkout v0.3.0
   ```

2. 使用 uv 依鎖檔同步環境：

   ```bash
   uv sync --frozen
   ```

3. 啟動正式服務：

   ```bash
   uv run uvicorn server.main:app --host 0.0.0.0 --port 8000
   ```

此版本不需要資料庫 migration。重新啟動或替換服務前，必須先確認目前沒有需要保留的房間或對局。

## 已知限制

- 房間與遊戲狀態仍儲存在單一 Python process 的記憶體中。服務重啟時，現有房間與對局不會保留。
- 請勿使用多 worker 或多 replica。
- 本次 release 流程不包含正式容器替換、registry 發布或正式環境 cutover。
